# Numeris-muisti

## 2026-05-06

- `LegacyDataMigrationService` hoitaa kaynnistyksen yleisen legacy-tuonnin Cloudflarelle, Web Analyticsille ja Search Consolelle.
- Vanhan Pulse-lahteen tiedot on keskitetty `LegacyAppSource`-määrittelyyn: SQLite-config luetaan polusta `%AppData%\com.finnvek.pulse\pulse.db`.
- Vanhat legacy keyring -salaisuudet luetaan Windows Credential Managerista Rust keyringin `<username>.Pulse`-kohdemallilla ja kopioidaan Numeriksen `CredentialVault`iin. Vanhoja legacy-avaimia ei poisteta automaattisesti.
- Tuotuihin yhteysconfigeihin lisataan `ImportSource = "legacy-pulse-tauri"`, eika uusiin configeihin kirjoiteta plain text -salaisuuksia.
- Sources-sivun integraatiotesteille lisattiin yhteinen `ConnectionTestResult`-malli. Cloudflare-, Web Analytics- ja Search Console -testit kayttavat samoja tallennettuja credentialeja kuin sync ja ajavat kevyen live-kyselyn ennen varsinaista synkronointia.
- `SettingsStore` lisattiin tallentamaan `ShellViewModel`in `SelectedPeriod`, `SelectedDomain` ja `LastPage` JSONiin `AppPaths.SettingsPath`-polkuun. `MainWindow` palauttaa viimeksi avatun NavigationView-sivun kaynnistyksessa.
- `ShellViewModel` muutettiin CommunityToolkit.Mvvm partial property -malliin. `Numeris.csproj` sai `<LangVersion>preview</LangVersion>`-asetuksen, koska partial properties vaatii C# 13/preview -kieliversion nykyisella toolchainilla.
- Unpackaged-kaynnistys kaatui ennen `App.OnLaunched`-metodia Windows App SDK:n DeploymentManager-auto-initializerissa virheeseen `REGDB_E_CLASSNOTREG`. Korjaus oli lisata `Numeris.csproj`-tiedostoon `<WindowsPackageType>None</WindowsPackageType>`, jolloin unpackaged build kayttaa bootstrap-auto-initializeria.
- Search Console -syncin HTTP 401 `CREDENTIALS_MISSING` johtui token-vastauksen snake_case-kentista. `SearchConsoleClient.TokenResponse` mapattiin eksplisiittisesti `access_token` ja `refresh_token` -kenttiin, ja tyhjalle access tokenille lisattiin guard ennen API-kutsuja.
- CrUX-, PageSpeed- ja Bing Webmaster Tools -integraatioiden ensimmainen core-toteutus lisattiin Sources-sivulle. CrUX ja PageSpeed kayttavat Google API key -avaimia `CredentialVault`ista; Bing kayttaa Bing Webmaster API keyta ilman OAuthia. `performance_urls` sisaltaa oletuksena `https://finnvek.com/` ja `https://knittoolsapp.com/`, ja URL:eja voi lisata manuaalisesti myohemmin.
- Performance-sync hakee CrUX `records:queryHistoryRecord` -dataa origin- ja URL-tasolla form factoreille ALL/PHONE/DESKTOP/TABLET, ajaa PageSpeedin MOBILE/DESKTOP-strategioilla ja tallentaa seka normalisoidut rivit etta raw JSONin. Bing-sync ajaa read-only Webmaster API -metodeja, normalisoi rank/query/page-rivit ja tallentaa muun datan `bing_raw_items`-tauluun.
- API-integraatioiden virhepolkuja kovennettiin: Google/Bing-clientit kayttavat sanitisoitua `ApiRequestException`-mallia, CrUX History -parsinta vastaa `collectionPeriods`-taulukkoa ja kasittelee `NaN`-timeseries-arvot nullina, PageSpeed-syncissa on yhdenaikaisen ajon rajoitus, kevyt throttling ja 429/5xx retry/backoff. Bing Webmaster -automaattisync rajattiin ydindataan (`GetUserSites`, rank/query/page stats, crawl stats/issues); detail-metodit dokumentoitiin `BING-WEBMASTER-SYNC.md`:aan myohempaa erillistoteutusta varten.
- Kaikki ViewModelien `[ObservableProperty] private field` -maarittelyt muutettiin CommunityToolkit.Mvvm partial property -muotoon MVVMTK0045-varoitusten poistamiseksi. `Numeris.Tests` tarkistaa jatkossa, ettei private field -muoto palaa ViewModel-koodiin.
- Projektin juureen lisattiin `CODE_REVIEW_QUESTIONS.md`, jossa on seuraavaa laajaa koodikatselmusta varten kysymykset arkkitehtuurista, API-integraatioista, SQLite-skeemasta, tietoturvasta, UX:sta ja testeista.
- Integraatioarkkitehtuuria yhtenaistettiin: `SourcesViewModel` pilkottiin lahdekohtaisiin `Numeris.ViewModels.Sources` -ViewModeleihin, sync-palveluiden suora `SqliteDatabase`-kirjoitus poistettiin ja ingest-kirjoitukset siirrettiin repositoryihin. `SiteIdentity` lisattiin yhdeksi domain/origin/home page URL -normalisoinnin totuudeksi, ja `PerformanceUrl` delegoi sille. `connections`-registryyn lisattiin erilliset `crux`- ja `pagespeed`-rivit vanhan `perf`-koontitilan rinnalle.
- SQLite-datareviewin korjaukset lisattiin: skeemalle tuli `PRAGMA user_version` -pohjainen versioitu migraatiopolku (`CurrentSchemaVersion = 2`), `bing_page_stats` sai Date-kentan ja avaimen `(site_url, page_url, date)`, Bing query/page raw item -avaimet sisaltavat Date-osan, ja repository-batcheille lisattiin `WriteTransactionAsync`.
- Raw API JSON -tallennus rajattiin `RawJsonStoragePolicy`-luokkaan. PageSpeed-runien maara pidetaan per URL/strategy rajattuna, Bing raw -riveille on aikapohjainen retention, ja raw/detail JSON redaktoi tokenit, API-avaimet, client secretit, salasanat ja bearer-arvot ennen hallittua katkaisua ja SQLite-tallennusta.
- Root-tason viimeistelysuunnitelma lisattiin tiedostoon `CORE-COMPLETION-PLAN.md`. Se kokoaa core-tilan, jaljella olevat verification/smoke-testit, julkiset sopimukset ja suositellun commit-jarjestyksen.
- `Numeris.Tests` on framework-dependent testiharness, jotta se voi viitata non-self-contained WinUI-paaprojektiin ilman `NETSDK1150`/`NETSDK1151`-virhetta. `Numeris.slnx` pidetaan x64-verifikaatioratkaisuna, jotta CLI-build ei sekoita ARM64-paaprojektia x64-testiharnessiin; itse paaprojekti sailyttaa x86/x64/ARM64 runtime identifierit publishia varten.
- WinUI-paaprojekti pakottaa MSBuildin `AnyCPU`-oletuksen x64:ksi, koska packaged .NET app host -build ei voi olla processor-architecture neutral. Tama tarvitaan erityisesti `dotnet run --project Numeris.Tests/Numeris.Tests.csproj` -polussa, jossa ProjectReference voi muuten rakentua AnyCPU:na.
- `ConnectionTestResult`in sopimus on yksinkertainen `Ok` + `Message`. Upstream status code pysyy `ApiRequestException`-polussa, ja lahde-ViewModelien seka sync-testien UI-virheet kulkevat `ApiErrorMessage.Sanitize(ex)` -sanitoinnin kautta.
- Projektin juureen lisattiin `TESTING_AND_MAINTAINABILITY.md`, joka kokoaa integraatioiden yksikkotestikohteet, MSTest-pohjaisen test framework -suosituksen, MVVM Toolkit partial property -tilan ja pre-MSIX smoke-testit.
- WinUI-visuaalisen jarjestelman ensimmainen vaihe keskitettiin `Numeris/Themes/Tokens.xaml`-resursseihin: `AppBackgroundColor` on `#444444`, kortti-, chart-, status-, teksti-, spacing-, taulukko- ja radius-tokenit ovat yhteisia, `MainWindow` kayttaa `MicaBackdrop`ia rauhallisena shell-materiaalina ja fallbackina, ja leveassa ikkunassa expanded left `NavigationView` -paneelia ikonipelkan railin sijaan. NavigationView kayttaa lapinakyvaa shell-taustaa seka `NavigationLayerBrush`-resurssia. Dashboard toimii referenssisivuna uusille KPI-, chart- ja status strip -pinnoille. Cloudflare-, Search- ja Health-sivut kayttavat samoja card/chart/list/tab-tyyleja. Sources-sivu on integration settings -nakyma, jossa jokainen lahde on oma yhteista `ContentCardBorderStyle`-pintaa kayttava integraatiokortti; vanha mock-dataa mainitseva ohjeteksti poistettiin. LiveCharts-varit siirrettiin `Numeris.Themes.ChartPalette`-luokkaan, jotta ViewModelit eivat sisalla kovakoodattuja design-hexeja.
- Sovelluksen nakyva paatausta on nyt shell-tason bitmap `Numeris/Assets/AppBackdrop.png`, jonka `MainWindow` piirtää `AppBackdropImage`-kerroksena `MicaBackdrop`/`#444444`-fallbackin paalle ja himmentaa `AppBackdropScrimBrush`-kerroksella. Vanha Dashboard-kohtainen `OverviewHeroBackdrop.png`-hero poistettiin XAML- ja csproj-kaytosta, jotta kaikki sivut jakavat saman taustavastuun. Taustan visuaalinen sopimus on tumma, viivaton, pehmea lasi/satiininauha-tyylinen bitmap, jossa honey amber -korostus on hienovarainen ja paasisaltoalue pysyy matalakontrastisena.
- AppBackdropin ensimmainen kaytto oli liian aktiivinen UI:n alla, joten tausta alistettiin sisallolle: `AppBackdropOpacity` laskettiin 0.72:een, scrim vahvistettiin `#B3000000`-arvoon, content layer muutettiin tummaksi `#26000000`-kerrokseksi, NavigationViewin content-grid border poistettiin, kortti-/control-pinnat ja chart-gridin kontrasti vahvistettiin, chartien muted-sarja keskitettiin `ChartMutedColor`-tokeniin ja native titlebarin varitys sovitettiin tummaan shelliin `ConfigureTitleBarColors`-polulla.
- Analytics-sivujen header-rakenne yhtenaistettiin `PageHeaderBorderStyle`-layoutiin: Overview, Cloudflare, Search ja Health sijoittavat otsikon, domain/period/refresh-kontrollit ja sivukohtaiset tabit samaan header-alueeseen, mutta header ei piirra omaa taustaa, reunaa tai korttimaista kehysta. Period-combojen data lahtee jaetusta `PeriodOptions.All`-listasta ja `Period.DisplayLabel()`-extensionista, jotta UI:ssa naytetaan `Last 7 days` eika enum-arvoa `Last7Days`. `OneDecimalConverter` kayttaa `CultureInfo.InvariantCulture`ia, jotta englanninkielisessa UI:ssa desimaalierotin pysyy pisteena. Healthin toimintanapit kayttavat `PrimaryActionButtonStyle`-tyylia AccentButton-oletuksen sijaan, ja Cloudflare-sivun sisalto scrollaa nimetyn page-level `PageScrollViewer`in kautta.
- Kortti-, chart- ja kontrollipinnat muutettiin pois vaaleasta harmaasta white-overlaysta kohti tummempaa black-glass-sopimusta, jotta pinnat istuvat paremmin mustaan/honey amber -taustakuvaan: `ContentLayerColor #52000000`, `CardSurfaceColor #66000000`, `ControlSurfaceColor #50000000`, `ChartPanelColor #5C000000` ja hillitympi `NumerisCardBorderColor #26FFFFFF`. Header on poikkeus: se on lapinakyva layout-alue, jotta sivuotsikot eivat nayta korteilta.
- NavigationView-paneelin oma vignette/taustasavy poistettiin tekemalla `NavigationLayerColor` kokonaan lapinakyvaksi (`#00000000`). `NavigationViewDefaultPaneBackground`, `NavigationViewExpandedPaneBackground` ja `NavigationViewTopPaneBackground` jatkavat `NavigationLayerBrush`-resurssin kautta, joten vasen nav-alue nayttaa samaa `AppBackdrop.png`-taustaa kuin muu shell ilman erillista varirajaa.
- Content-alueen oma tumma taustakerros poistettiin myos (`ContentLayerColor #00000000`), jotta vasen nav ja oikea sisaltoalue nayttavat samaa `AppBackdrop.png`-taustaa. Kortti-/kontrollipintoja kevennettiin edellisesta liian mustasta tasosta: `CardSurfaceColor #42000000`, `ControlSurfaceColor #38000000`, `ChartPanelColor #48000000` ja `NumerisCardBorderColor #30FFFFFF`.
- Windowsin natiivi ylapalkki korvattiin `MainWindow`in omalla lapinakyvalla `AppTitleBar`-rivilla. `ConfigureCustomTitleBar` asettaa `ExtendsContentIntoTitleBar = true`, rekisteroi `SetTitleBar(AppTitleBar)`-vetopinnan ja lukee caption button -varit `Tokens.xaml`-resursseista, jolloin `Numeris`-nimi on vasemmassa ylakulmassa ja ylapalkki sulautuu samaan `AppBackdrop.png`-taustaan.
- LiveChartsin WinUI-teemavastuu keskitettiin `Numeris.Themes.ChartTheme`-luokkaan. Sivujen chart-hostit luovat `CartesianChart`-kontrollit sen kautta ja asettavat ne `ChartTheme.CreateChartSurface`-pintaan, joka piirtää hillityn honey amber / valkoisen 2.5D mesh-taustan chartin alle. Draw margin -tausta ei jaa mustaksi oletuspinnaksi, legend/tooltip-tekstit kayttavat chart-paletin tekstivaria, ja ViewModelien akselit viimeistellaan `ChartTheme.StyleXAxis`/`StyleYAxis`-helperien kautta.
- Cloudflare Traffic -sivun Top countries -kortti kayttaa vain `HorizontalBars`-kontrollia ja samaa `BarRow`-listaa kuin muut listavisualisoinnit. `CountryTrafficMap`-, WebView2-, MapLibre-, topojson- ja world-atlas -vastuut poistettiin kokonaan, samoin `Numeris/Assets/Maps`-offline-assetit ja `Map`/`Bars`-vaihto. Maakohtainen tarkka lukeminen tapahtuu nyt pelkasta palkkilistasta.
- Bing ja web performance erotettiin omiksi raportointinakyimikseen. `BingPage` lukee `BingRepository`n kautta Bing Webmaster -traffic-, query-, page- ja crawl/raw-yhteenvedot; `PerformancePage` lukee `PerformanceRepository`n kautta CrUX Core Web Vitals -statukset/trendit, PageSpeed latest runit, score-trendit ja audit issue -listat. `SourcesPage` sailyy vain avainten, kohdelistojen, testauksen ja syncin paikkana.
- Overview on jatkossa koontinakyma: Cloudflare visitors, Google clicks, Bing clicks, Web Vitals -status, PageSpeed mobile ja viimeisin sync. Google Search, Bing ja Performance pitavat omat detail-taulukkonsa ja charttinsa erillaan, jotta kayttajan mentaalimalli pysyy selkeana.
- Mock-data poistettiin sovelluksen kaynnistyspolusta: `MockSeeder` poistettiin, `App.OnLaunched` ei enaa siemenna esimerkkiriveja, yhteyksien tyhja tila on `disconnected`, ja SQLite-skeemaversio 3 siivoaa aiemmat tunnetut mock-rivit analytiikkatauluista. Jatkossa raporttinakymat nayttavat vain live-syncista, legacy-tuonnista tai kayttajan konfiguraatiosta syntyvaa dataa.
- Search Console Indexing -tabiin lisattiin URL Inspection API -pohjainen tarkistuspolku. `SearchConsoleClient.InspectUrlAsync()` kutsuu `https://searchconsole.googleapis.com/v1/urlInspection/index:inspect`, `SearchConsoleSyncService.InspectSitemapUrlsAsync()` tarkistaa valitun domainin aktiiviset sitemap-URLit olemassa olevalla OAuth-yhteydella, ja `SitemapRepository.UpdateInspectionAsync()` tallentaa `verdict`, `coverage_state`, `indexing_state`, `last_crawl_time`, `page_fetch_state`, `crawled_as` ja `last_inspected_at` -kentat. Search-sivun ylaoikea refresh-nappi ajaa Indexing-tabilla URL Inspection -paivityksen; erillista Inspect URLs -nappia ei pideta nakymassa.

## 2026-05-11

- YouTube lisattiin omaksi integraatioksi ja raportointinakymaiksi. `YouTubePage` nayttaa yhden autentikoidun oman kanavan overviewin, videot, maat, traffic sourcet, laitteet ja retentionin; v1 ei tee appi-/domain-jakoa.
- Google OAuthin token-kasittely keskitettiin `GoogleOAuthClient`-luokkaan. `GoogleOAuthFlow` saa scope-listan parametrina, Search Console kayttaa edelleen webmasters-scopea ja YouTube kayttaa `youtube.readonly` + `yt-analytics.readonly` -scopeja.
- YouTube-salaisuudet tallennetaan vain `CredentialVault`iin avaimilla `Numeris.YouTube.ClientSecret` ja `Numeris.YouTube.RefreshToken`; `connections.config` sailyttaa vain client ID:n, channel ID:n, channel titlen ja validointiajan.
- SQLite-skeema nostettiin versioon 4. YouTube-data tallennetaan tauluihin `youtube_channels`, `youtube_videos`, `youtube_daily`, `youtube_video_stats`, `youtube_countries`, `youtube_traffic_sources`, `youtube_devices` ja `youtube_retention_points`; `connections` sai oman `youtube`-rivin.
- YouTube-dataflow noudattaa muuta integraatioarkkitehtuuria: `YouTubeDataClient` ja `YouTubeAnalyticsClient` hakevat API-datan, `YouTubeSyncService` orkestroi tokenit ja aikavalit, `YouTubeRepository` tekee SQLite-kirjoitukset transaktioissa ja `YouTubeViewModel` lukee raportointidatan UI:lle.

- `HorizontalBars` nayttaa tyhjan tilan ja lukee label/value-sarakkeiden mitat tokeneista. Taulukkoheaderit käyttävät `DataTableHeaderBorderStyle`-tyylia.
